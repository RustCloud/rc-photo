# rc-photo — галерея «Фото» для RustCloud

Плагин [RustCloud](https://git.luklu.com/pi/rustcloud) `rc-photo` (в панели — «Фото»): фото и видео из папок пользователя —
лента по дням и месяцам, фильтры, просмотр на всю страницу. Без нейросетей: только то, что есть
в самих файлах.

- **Лента** — ровные ряды, фото сохраняют пропорции; заголовки месяцев и дней; полоса годов справа
  для быстрой прокрутки. Рисуется только видимое, поэтому десятки тысяч фото не тормозят.
- **Фильтры** — фото или видео, избранное, с геометкой, период, годы, камеры, объективы, папки
  (с вложенными), форматы, ориентация; поиск по имени, папке, камере. Рядом с каждым значением —
  сколько файлов останется.
- **Просмотр** — фото «вырастает» из своей миниатюры; сначала миниатюра, потом оригинал. Стрелки,
  свайп, колесо и щипок — зум, двойной клик — 2,5×. Сведения: дата, камера, объектив, выдержка,
  диафрагма, ISO, координаты. Избранное (`f`), скачивание, лента соседних фото.
- **Форматы** — всё, что читает ffmpeg сервера: JPEG, PNG, WebP, GIF, HEIC, AVIF, TIFF, RAW
  (CR2, CR3, NEF, ARW, DNG…); видео MP4, MOV, MKV, WebM… HEIC, RAW и TIFF браузер не показывает —
  для них галерея делает большое превью 2560 px.
- **Видео** — то, что браузер играет сам (H.264 в MP4), идёт по ссылке с перемоткой; остальное —
  HLS с сервера: перепаковка, если браузер знает кодек, иначе перекодирование в H.264 (hls.js).
- **Выбор нескольких** — кружок на плитке; когда что-то выбрано, клик выбирает, Shift — диапазон,
  Ctrl — по одному; кружок у даты выбирает весь день, `Ctrl+A` — всё показанное, `Esc` снимает.
  Выбранное можно добавить в избранное, скачать или удалить (`Delete`) разом.
- **Загрузка** — перетащите фото и видео на страницу (или кнопка «Загрузить»). Папку целиком
  перетащить можно, только если браузер даёт странице-песочнице её прочитать (Chromium не даёт) —
  иначе галерея так и скажет.
  Файлы идут прямо на сервер, мимо плагина, поэтому размер не ограничен (только квота и
  `max_upload_mib`); видно прогресс и ошибки по каждому файлу. Если папок несколько, галерея
  спросит, куда класть, и запомнит выбор. Занятое имя получает номер: `IMG_1 (1).jpg`; вложенные
  папки сохраняются.
- **Удаление** — значок корзины в просмотре или `Delete`, с подтверждением; файл попадает в корзину
  облака. Если папка дана только на чтение, галерея попросит дать её ещё раз с правом записи.
- **Люди** (с 0.5.0, выключены, пока пользователь их не включит) — сервер находит лица на фото, галерея
  группирует их по людям. В фильтрах — лицо каждого человека: клик показывает его фото (несколько —
  фото, где они вместе), клик по имени — назвать или скрыть. Имя, которое уже есть у другого,
  предлагает их объединить. В сведениях фото — кто на нём. «Удалить данные о лицах» стирает всё.

## Как устроен

| Где                         | Что                                                                  |
|-----------------------------|----------------------------------------------------------------------|
| [src/media.rs](src/media.rs) | фоновые задачи: `media` — описать файл и сделать миниатюру; `scan` и `prune` — «Пересобрать» |
| [src/index.rs](src/index.rs) | индекс в AppData: `index/<00–3f>.json`, файл выбирается по хэшу id    |
| [src/api.rs](src/api.rs)     | JSON для страницы: состояние, ссылки, видео, избранное, удаление, пересборка |
| [src/upload.rs](src/upload.rs) | ссылки для загрузки (`links.upload`): подпапки, свободные имена  |
| [src/faces.rs](src/faces.rs) | задача `faces`: лица фото и их векторы через `use.onnx`; `faces/<00–3f>.json` |
| [src/vision.rs](src/vision.rs) | математика вокруг моделей: тензоры, выход YOLO, NMS, выравнивание по 5 точкам |
| [src/people.rs](src/people.rs) | задача `people`: группировка лиц в людей; имена и объединения от страницы |
| [ui/](ui)                    | страница: лента, фильтры, просмотр; [hls.js 1.5.20](ui/vendor) (Apache-2.0) |

- Пользователь сам выбирает папки (`files = "folder"`). Галерея не меняет файлы, а только загружает
  новые и удаляет по просьбе пользователя (`files_write`, с 0.2.0); новые папки просит сразу с
  правом записи.
- Загрузка: страница просит у плагина ссылки (`POST /api/uploads`, по 30 файлов) и отправляет
  каждый файл на свою ссылку, по 3 одновременно. Задачи `media` для загруженного сервер ставит сам.
- Свои изменения плагин событиями не получает, поэтому после удаления он сам ставит задачу
  `media` — она убирает файл из индекса вместе с миниатюрой.
- Задачи ставит сервер — по событиям `file.granted`, `file.created`, `file.changed`,
  `file.deleted`, `file.moved` для `image/*` и `video/*`. Плагину не нужно обходить папки.
- Метаданные и картинки делает ffmpeg сервера (`use.ffmpeg`): миниатюра 720×480 WebP,
  превью 2560 px JPEG. Всё лежит в AppData пользователя (`.appdata/rc-photo/`) и занимает его квоту —
  примерно 20–40 КБ на фото, у HEIC и RAW ещё 300–600 КБ на превью.
- Индекс, миниатюры и оригиналы страница получает по ссылкам `links.create`: сервер отдаёт их сам,
  мимо плагина, с `ETag`, и браузер их кэширует.
- Порции задач одного пользователя идут по одной (`workers = 1`): индекс переписывают только они.

### Лица

- Модели скачивает сервер (`[[downloads]]`, с Hugging Face) в хранилище плагина:
  - [YOLO11n-face с 5 точками](https://huggingface.co/huygiatrng/yolov11n-face-pose-5kp) (MIT, 11 МБ) — находит лица;
  - [ArcFace w600k_r50](https://huggingface.co/immich-app/buffalo_l) из buffalo_l InsightFace (только
    некоммерческое использование, 174 МБ) — вектор из 512 чисел на лицо.
- Сервер только запускает модели (`use.onnx`); всё вокруг — в плагине. На фото — одно декодирование:
  `image-tensor` даёт картинку до 1600 px, из неё плагин делает вход детектора (640×640), разбирает
  его выход, поворачивает каждое лицо по 5 точкам к шаблону ArcFace (112×112) и отправляет лица фото
  одной пачкой.
- Задача `faces` на каждое фото ставится, когда пользователь включает лица, и потом вслед за `media`.
  Вектор хранится квантованным (512 байт, base64) рядом с рамкой лица в `faces/<00–3f>.json`.
- Задача `people` после порций `faces` группирует все лица: лицо без человека присоединяется к
  человеку, к среднему лицу которого оно ближе всего (сходство ≥ 0,45); оставшиеся близкие лица
  (≥ 0,5, хотя бы 3, ширина от 48 px) становятся новыми людьми. Итог — `people.json`: люди, их фото,
  лицо для показа. Пока `faces` ещё идут, группировка ждёт 300 новых фото.
- Имена, скрытые и объединения пишет только страница (`people-names.json`), задача их только
  читает — так они не теряются, когда задача переписывает лица.
- Всё — в AppData пользователя; на фото с лицами это примерно 1 КБ на лицо.

## Что нужно серверу

RustCloud с API плагинов **0.2.13** (`use.onnx`) и ffmpeg (`media_tools_dir`; в Docker-образе есть).
Администратор при включении утверждает доступ к папкам, запись (`files_write`), `use.ffmpeg`,
`use.onnx` и сеть до Hugging Face (`huggingface.co`, `*.hf.co`) — для загрузки моделей.
Обновление, которое добавляет права (0.5.0 — нейросети), отключает плагин до подтверждения.

## Сборка и установка

Версия в `manifest.toml` и `Cargo.toml` поднимается с каждым изменением.

```sh
rustup target add wasm32-wasip2
cargo test
cargo build --release --target wasm32-wasip2
mkdir -p dist/rc-photo && cp manifest.toml dist/rc-photo/
cp target/wasm32-wasip2/release/rc_photo.wasm dist/rc-photo/app.wasm
(cd dist && zip -r rc-photo.zip rc-photo)
```

«Администрирование → Плагины → Установить плагин…» → `rc-photo.zip` → включить.

В Forgejo Actions это делает [.forgejo/workflows/build.yml](.forgejo/workflows/build.yml): на каждый
push — проверка версий (`manifest.toml` = `Cargo.toml`, `api` = версия `wit/app.wit`), fmt, clippy,
тесты, синтаксис JS, сборка; артефакт `rc-photo-<версия>` скачивается zip-архивом, который ставится как есть. Тег `v<версия манифеста>`
(`v0.3.0`) ещё и публикует релиз с `rc-photo.zip` и его SHA-256.

`wit/app.wit` — копия `crates/plugin-api/wit/app.wit` сервера той версии, что в `manifest.toml`.

## Проверка в браузере

[e2e/rc-photo.mjs](e2e/rc-photo.mjs) — на чистом сервере ставит плагин, создаёт папки с фото (JPEG
с EXIF рисуются на canvas) и видео, ждёт задачи и проходит страницу в Chromium: лента, фильтры,
просмотр, зум, HEIC, видео, удаление (с запросом записи), выбор нескольких (диапазон, день, всё) с избранным и удалением, загрузка настоящим перетаскиванием через CDP (40 МБ, занятое
имя, папка, выбор папки, вложенные папки, папка только для чтения), тёмная тема, телефон. Снимки экрана — в `/out`.

```sh
docker run --rm --network host -v $PWD/e2e:/e2e -v $PWD/dist/rc-photo.zip:/e2e/rc-photo.zip \
  -v $PWD/out:/out -w /e2e mcr.microsoft.com/playwright:v1.64.1-noble \
  sh -c 'npm i -s playwright@1.64.1 >/dev/null && node rc-photo.mjs http://127.0.0.1:8090'
```

Образцы HEIC и видео, если они есть, кладутся в `e2e/samples/` (в git их нет).

[e2e/faces.mjs](e2e/faces.mjs) — лица: на чистом сервере с `use.onnx` загружает фото людей из
`e2e/faces/<человек>_<n>.jpg` (в git их нет), включает лица на странице, ждёт загрузку моделей и
задачи, сверяет людей с именами файлов; называет человека, фильтрует по нему, смотрит сведения фото,
объединяет двоих по имени и всё удаляет.
